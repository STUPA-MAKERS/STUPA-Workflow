# The tree sorts by kind, then by area and topic

A spec file must be below one of these kind folders:

| Folder | Kind | Content |
| --- | --- | --- |
| `style/` | `style` | How code, tests, migrations, commits, specs and texts must look. |
| `requirements/functional/` | `functional` | What the application must do. |
| `requirements/non-functional/` | `non-functional` | How well the application must do it: security, privacy, performance, usability, accessibility, compatibility. |
| `protocols/` | `protocol` | The formats that the application exchanges: HTTP and WebSocket messages, webhooks, MCP, files and exports. |

Below the kind folder, the first folder is the area, for example `meetings/`. The folder below
it is the topic, for example `voting/`. The topic folder holds the rule files.

The area of a protocol spec must be an area of `requirements/functional/`. If a functional topic
uses the format, the protocol spec must have the same topic, for example
`protocols/integrations/webhooks/`. A protocol spec and its rules then have the same path.

Test: `scripts/check_specs.py`.
