The user gave this backlog on 2026-06-14, in priority order. Rule: ask the user about the design
decisions of every item ([[ask-all-design-decisions]]).

1. Make the PWA name config-driven. Today it is hardcoded to "StuPa". Expose it on the existing
   Branding & Texts admin page. The PWA manifest `name` and `short_name` are static at build
   time, so the runtime-config approach still needs a decision.
2. Tree-filters (left panel): fade the content at the TOP and BOTTOM edge while the user
   scrolls, like the timeline on the meetings tab.
3. Search in /expenses and /invoices must be fuzzy, match EVERY field and sort by match ranking.
   Add the same search line to /applications and /meetings.
4. All filters must also filter in the BACKEND where that makes sense. This keeps large data
   sets off the frontend.
5. Add a permission for read-only access to ALL meetings.
6. Add useful pre-fills for text inputs:
   6-1. The create-meeting dialog becomes 2 steps. Step 1 takes the date, the Gremium and the
        time. Step 2 pre-fills the name with `Sitzung des <committee> am <date>`.
   6-2. Pre-fill the vote question for application agenda items with
        `Soll der Antrag <application-name> wie beschrieben gefördert werden?`.
7. Formly checkboxes have more space above than below. Make the space equal.
8. Meetings header: align the title with the grey bar. Move the breadcrumbs further right
   GLOBALLY, so that the RIGHT edge of the breadcrumbs aligns with the right edge of the site
   logo. Earlier breadcrumb-align attempts were reverted, see git fc07008.
