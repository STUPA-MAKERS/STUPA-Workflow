# Protocol — `backend/app/modules/protocol`

**Does:** Backs the protocol of a meeting as editable Markdown and embeds vote results as snippets. On finalize it renders the document to PDF via the typst render service, stores the PDF in MinIO, and mails it to the gremium mailing list. The render runs asynchronously in an arq worker (`status='rendering'`). Without Redis it falls back to a synchronous render.

**Key files:**
- `models.py` — `Protocol` (1:1 per meeting), `ProtocolVoteRef` (embedded-vote anchor), and `PROTOCOL_STATUSES`.
- `router.py` — the FastAPI routes. It wires `ProtocolService` to the T-20 render infrastructure (storage and mail from app.state, typst from settings) and applies the RBAC gating.
- `service.py` — `ProtocolService`: lifecycle (`get_or_create`, `update_markdown`, `embed_votes`, `start_finalize`, `finalize`, `revert_to_draft`), agenda assembly, dual internal/public render, mail send, recipient resolution, quorum.
- `markdown.py` — DB-free Markdown builders: `build_protocol_document` (YAML frontmatter + body), `build_vote_snippet` (`> [!abstimmung]` callout), `demote_headings`, `sanitize_user_markdown` (RCE/path-traversal hardening), `protocol_variant_for`.
- `schemas.py` — camelCase wire models: `ProtocolOut`, `ProtocolPatch`, `ProtocolVotesBody`.
- `public.py` — the public version: the snapshot models (`PublicSnapshot`, `PublicTop`, `PublicDecision`, `PublicAttendance`), `apply_public_snapshot`, the semester helpers (`semester_of`, `semester_range`: `ws-YYYY` = October to March, `ss-YYYY` = April to September), the fail-closed `visible_clause()` and `PublicProtocolService` (the reads of the public page).
- `public_router.py` — the auth-free routes under `/api/public/` (gremien, protocols, semesters, detail, PDF).
- `queue.py` — `ArqProtocolRenderQueue` / `protocol_render_queue_from_pool` with `PROTOCOL_RENDER_TASK_NAME = "render_protocol"`. It sets no `_job_id` on purpose, because a re-finalize after a rollback must enqueue a fresh job.
- `../../../worker/protocol.py` — the `render_protocol` arq task: builds the service from `ctx` deps, calls `finalize`, retries on transient (`ServiceUnavailableError`) up to `pdf_max_tries`, reverts to `draft` on permanent failure, then broadcasts `meeting_state`.

**Domain / data model:**
- `protocol` — UUID pk, `meeting_id` (FK meeting, CASCADE) with `UniqueConstraint uq_protocol_meeting`, `gremium_id` (FK gremium, CASCADE, indexed), `markdown` (Text, editor backing), `pdf_storage_key` / `public_pdf_storage_key` (nullable MinIO keys), `author`, `status` (Text, CheckConstraint `protocol_status` IN draft/rendering/final, default `draft`), `sent_at`, `cd_variant` (copied from gremium → selects the render variant), `public_withheld` (bool, default false: hold back this protocol from the public page), `public_content` (JSONB snapshot of the public version), `public_search_text` (plain text of the public TOPs for the search), `public_pdf_size`, plus TimestampMixin. The unique constraint is the 1:1 that makes create idempotent. Migration `bf0309071fb4` adds the public columns and `gremium.protocols_public`.
- `protocol_vote_ref` — UUID pk, `protocol_id` (FK protocol, CASCADE, indexed) + `vote_id` (FK vote, CASCADE). `UniqueConstraint uq_protocol_vote_ref(protocol_id, vote_id)` makes embedding idempotent (no duplicate snippet).
- **Lifecycle:** `draft → rendering → final`. `rendering` means finalize started and the worker renders in the background. A permanent render failure rolls back to `draft`, so the protocol never sticks in `rendering`. `final` is read-only and sets `pdf_storage_key` + `sent_at`.
- Migration 0001 (the baseline) creates the tables via `Base.metadata.create_all`, idempotently on both a fresh and an existing schema.

**API surface:**
- `POST /api/meetings/{meeting_id}/protocol` — create OR load, idempotent. It answers 409 while the meeting is still `planned`, because the service creates the protocol when the meeting starts, not before. write access (`MeetingService.can_write`: `session.manage` or `protocol.write` in the Gremium, the assigned protokollant, or admin).
- `GET /api/meetings/{meeting_id}/protocol` — read, 404 if none. The frontend polls this path during a background render. read access (`assert_can_read`: Gremium member, pool substitute, delegation recipient, `meeting.view_all`, admin).
- `PATCH /api/protocols/{protocol_id}` — update the Markdown body. It answers 409 when the status is final or rendering. Write access.
- `POST /api/protocols/{protocol_id}/votes` — embed votes as snippets (idempotent). Write access. F25: only the votes of the protocol's own meeting (`vote.meeting_id == protocol.meeting_id`), else 422 `vote_not_in_meeting` and nothing is embedded.
- `POST /api/protocols/{protocol_id}/finalize` — set `rendering` and enqueue `render_protocol`. Without Redis it renders synchronously. `MeetingService.can_finalize`: write access AND the GREMIUM permission `protocol.finalize` in the Gremium of the meeting (or admin). Otherwise 403 `Missing permission(s): protocol.finalize`. F8/O13: only after the close of the meeting, else 409 `meeting_not_closed`. O2: once, also with several keepers: a `rendering` or `final` protocol gives 409 `protocol_not_draft`. After a failed render the protocol is a draft again, and a new call starts again. The start writes `protocol_finalize` (F12).
- `GET /api/protocols/{protocol_id}/pdf` — stream the internal PDF bytes server-side. Read access.
- `GET /api/protocols/{protocol_id}/pdf/public` — stream the redacted public variant (404 unless one was rendered: a non-public agenda item exists, or the gremium publishes its protocols). Same read perms.
- `PATCH /api/protocols/{protocol_id}` with `publicWithheld` — hold back the protocol from the public page or release it. Needs `authorize_finalize` (the publishing right), works in every status, writes `protocol_publication` (old and new value). The body needs `markdown` or `publicWithheld` (422 otherwise).
- `POST /api/protocols/{protocol_id}/finalize` takes the optional body `{publicWithheld}`. Absent or null KEEPS the stored value, so a draft held back with the PATCH stays held back on a plain finalize; a changed value writes `protocol_publication`. The audit entry `protocol_finalize` carries the resulting value.
- Public (no login, rate limit per IP `rl_public_protocols_ip_per_hour` / `rl_public_protocol_pdf_ip_per_hour`): `GET /api/public/gremien` (public gremien with at least one visible protocol: id, name, slug, `protocolCount`), `GET /api/public/protocols?gremium=&semester=&year=&q=&limit=&offset=` (newest meeting first; `q` searches the meeting title and `public_search_text`), `GET /api/public/protocols/semesters`, `GET /api/public/protocols/{id}` (the snapshot: TOPs, decisions, attendance counts, free text of a meeting without items), `GET /api/public/protocols/{id}/pdf` (the public PDF as an attachment, streamed through the API). There is NO public meeting route.

**Conventions & gotchas:**
- **RBAC server-side, fail-closed, per Gremium.** The service delegates every check to `MeetingService` (`can_write`, `can_finalize`, `assert_can_read`), so the protocol and the live stack share one rule and the OAuth scope cap. There is no global `meeting.manage` or `protocol.finalize` any more (migration `3a0b9672fcba`, decisions O2/O7). The forced Gremium roles `vorstand` and `manager` hold `protocol.finalize`; migration `b0c8fd389e10` also gave it to every existing role with `session.manage`. A role created later with `session.manage` but without `protocol.finalize` can write but gets 403 on finalize. The meeting payload carries `canFinalize`. The close never finalizes (O13): the frontend shows "Finalisieren & versenden" on a closed meeting with a draft protocol, and only when `canFinalize` is true.
- **Source of truth for the body is the per-agenda-item editor** when agenda items exist: `_assemble_from_agenda` stitches each `MeetingAgendaItem.body` (with `demote_headings`) + its non-cancelled `Vote` tally snippets, in `agenda_order()` (the order of the meeting page, so "TOP n" and the keeper TOP numbers agree). It falls back to the free-edited `protocol.markdown` only when the meeting has zero agenda items.
- **Header (`_header_meta` → `HeaderMeta`):** the attendance comes in three groups: `anwesend`, `entschuldigt` (F17) and `abwesend`. The keepers (Z3, O2) come from the `ProtocolKeeperPeriod` rows that started: one `KeeperLine` per period with the local times and the TOP numbers of the current agenda order (`None` for a period without an item or with a deleted one; the renderer then shows the time). The frontmatter carries them as `keepers` (a list of records) and, for an older render service, the legacy `protokoll` with every name once. A meeting without periods falls back to the name of `protokollant_id`. `started_at`, `datum` and `beginn` use the real start (`meeting.started_at`), else the planned date and time. The public variant carries no names and no keepers, only the data lines `Anwesend: n`, `Entschuldigt: n`, `Abwesend: n`.
- **Agenda item headings are top-level `#` with NO "TOP n:" prefix** — the renderer numbers the sections automatically as "TOP 1", "TOP 2". The builder demotes body headings one level, so the renderer does not count them as new agenda items.
- **Public vs internal (dual render):** if any agenda item has `non_public=True`, finalize renders BOTH a full internal PDF and a redacted public PDF. The redacted variant replaces the non-public agenda item bodies and votes with a placeholder and keeps the heading and the numbering. Only the **public** variant goes to the mailing list. Otherwise finalize renders one internal PDF and mails it.
- **No browser bucket links.** MinIO lives on the internal Docker network. `pdfUrl`/`publicPdfUrl` are app-relative `/api/protocols/{id}/pdf[/public]` paths that the API streams server-side. They are never presigned S3 URLs.
- **pre-commit-side-effects ordering:** the typst render runs BEFORE the commit. A render error rolls the session back and the protocol stays draft. The MinIO `put` and the mail enqueue happen ONLY AFTER a successful commit. A failed commit therefore leaves no orphan object and no stray send job.
- **Fail discipline:** storage is the deliberate on/off switch — if storage/typst is `None` (DEV/Demo/contract-CI without MinIO), finalize still completes (`final` + mail without PDF). A transient backend failure raises `ServiceUnavailableError` (503) → session rollback → re-finalizable. typst 4xx (e.g. a malformed formula) → `BadRequestError` (400, scrubbed reason).
- **Injection hardening (cross-link `typst`):** the body is user-written, but the typst render service converts it into JSON data before Typst sees it, so no part of it runs as code. `sanitize_user_markdown` stays as defense in depth: it strips the former pytex `eval`-escape (`[//]: # "EXPR"`) and `\iffalse{pytex(...)}\fi`, and neutralizes absolute and `..`-traversal image paths.
- **Idempotency.** `get_or_create` uses `INSERT … ON CONFLICT (meeting_id) DO NOTHING` plus a re-select. `embed_votes` uses `ON CONFLICT (protocol_id, vote_id) DO NOTHING`. `start_finalize` refuses a protocol that is not a draft (409), the worker's `finalize` no-ops on `final`. The mail dedupes via `compute_idempotency_key("protocol_finalized", id)`.
- **Quorum (`_quorate`):** the denominator is the roster of the meeting (`livevote.roster.meeting_roster_filter`: members whose term overlaps the meeting window plus every principal with an attendance record), never the members valid now. A re-render of a closed meeting therefore gives the same quorum after a membership ends or the OIDC sync removes it. The attendance lists of the header come from `meeting_attendance` only.
- **Mail recipients** = union of active gremium members (term window, email≠NULL, via `RecipientResolver`) ∪ configured `mail_list` extra distributors, then filtered by per-user "protocol" notification preference. PDF goes as an **attachment** (`protokoll.pdf`), not a login-gated link.
- **Variant:** a gremium `cd_variant` in {`stupa`,`asta`} selects the render variant `protocol-<cd>` (default logos). Any other value gives `None`, and the service reads the logos from the `gremium` frontmatter key.
- The worker (`worker/protocol.py`) reverts to draft and broadcasts `meeting_state` on both success and permanent failure, so live followers see the status flip. The frontend polls the GET endpoint, because GET avoids the write rate-limit (#429).

- **Guests (#17):** the header adds the data line `Gäste: n` (guests who took part) in both variants; a vote with guests gets the line "x Mitglieder + y Gäste anwesend · Abgegeben n · Mehrheit der abgegebenen Stimmen" in its snippet (`guest_vote_note`). Never a guest name. `start_finalize` pseudonymizes the guests.

- **Public protocols page (fail closed):** a protocol is public only when `status='final'`, `public_withheld` is false, `public_content` is set, and `gremium.protocols_public` is true. Everything else answers 404, never 403. Every answer under `/api/public/` carries `X-Robots-Tag: noindex` (`SecurityHeadersMiddleware`, plus the unhandled-exception handler in `shared/errors.py`, which runs outside the middleware). nginx adds the same header to the SPA routes `/protokolle(/…)`. The search `q` refuses control characters (NUL) with 422. The snapshot never holds a name: the attendance is counts only, a non-public TOP keeps its number only, the internal PDF is never served. The free text of a public TOP is published as written; the editor and the finalize dialog warn about names of third persons.
- **When the public version is built:** `finalize` renders the public PDF and stores the snapshot when a non-public TOP exists OR the gremium publishes (`protocols_public`); the snapshot comes from the same pass as the public PDF (`_assemble_from_agenda(tops=…)`, `_header_meta(public=True)`), so the page and the PDF agree. Without a non-public TOP the mail still carries the internal PDF. A switch of `protocols_public` from off to on enqueues `backfill_public_protocols` (arq; inline without Redis via `schedule_public_backfill`), which builds the missing snapshot and public PDF of every final protocol of the gremium, one commit per protocol; a transient error retries up to `pdf_max_tries`. Until then the protocol stays hidden. A failed enqueue only logs. The hourly cron `heal_public_protocols` (minute 40) runs the backfill for every public gremium with a final, not held back protocol that still lacks its public version (`gremien_missing_public`), so a failed or raced build heals without a new switch. A vote already pasted into the TOP text as a snippet still counts as a decision of the public TOP, marked `inText` so the detail page shows no second box. A permanent failure of the public build counts up `protocol.public_render_failures`; at `PUBLIC_RENDER_MAX_FAILURES` (3) the heal job skips the protocol (one warning), a successful build resets the count, and the backfill after a switch of the flag retries it. One failing gremium does not stop the heal loop.
