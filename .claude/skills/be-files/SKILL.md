name: be-files
description: Backend attachment storage for applications: multipart upload, libmagic MIME sniff plus extension match, MinIO/S3 object store. An arq worker runs the async ClamAV scan, quarantine gating guards the server-side download stream. Draft uploads of the wizard (Z4) live before the application with a draft token, the create binds them, an hourly cron purges expired ones. Chat files of ticket notes, to-do comments and application comments bind the same drafts and download under the read rule of their message. Models Attachment (scanned/scan_result/storage_key/draft_token_hash/draft_expires_at) and AttachmentDraftToken (token_hash/expires_at). Routes under /api/applications/{id}/attachments, /api/attachments/{id} and /api/apply/attachments. Use when working on file uploads, virus scanning, MinIO storage, signed/download URLs, or attachment access control in backend/app/modules/files.

# Files / Attachments — `backend/app/modules/files`

**Does:** Handles application attachment uploads. It caps the size, sniffs the real MIME type, stores the blob in MinIO/S3 and enqueues an async ClamAV scan. It serves a download only after a clean scan. Binary content never lives in the DB.

**Key files:**
- `router.py` — FastAPI routes: upload, list, signed-url, download stream, delete. The access checks mirror application read and edit. A cross-tenant request gets 404, so there is no existence oracle.
- `service.py` — `FilesService`: `upload`, `list_for_application`, `get_attachment`, `signed_url`, `download_bytes`, `assert_editable` (state lock for an applicant or creator delete), `delete`, `delete_for_application` (GDPR), `finalize_scan` (worker callback). `max_bytes`, `_is_infected`, `_ready_attachment` (quarantine gates).
- `models.py` — `Attachment` ORM model + `MAX_ATTACHMENT_BYTES` (10 MiB) DB CHECK, the two draft CHECKs, `DRAFT_KEY_PREFIX` (`drafts/`) and `BOUND` (the `application_id IS NOT NULL` filter). `AttachmentDraftToken` holds the lifetime of a draft token.
- `drafts.py` — draft uploads of the wizard (Z4): `DraftAttachments` (`upload`, `delete`, `token_is_valid`), `check_drafts` and `bind_drafts` (called by the application create), `hash_draft_token`, `invalid_token`, the problem codes `draft_token_invalid`, `draft_quota_exceeded`, `draft_attachments_missing`.
- `schemas.py` — `AttachmentOut` (id/filename/mime/size/scanned/is_comparison_offer), `SignedUrlOut` (url/expiresIn).
- `mime.py` — libmagic sniff + `ALLOWED_MIME_TYPES` allowlist, `_EXT_TO_MIME` ext↔mime match, `validate_upload`, `MimeRejected`.
- `../../shared/filenames.py` — the two names of an upload and the download header. `sanitize_display_name` (the stored `filename`, keeps Unicode), `sanitize_storage_name` (the ASCII last segment of the object key), `content_disposition` (the header of every download route). See the gotcha "Two names per upload".
- `storage.py` — `ObjectStorage` Protocol, `MinioStorage` (sync minio client via `asyncio.to_thread`), `build_object_storage`, `StorageError`.
- `scanner.py` — `VirusScanner` Protocol, `ClamdScanner` (clamd TCP INSTREAM), `ScanVerdict`, `build_scanner`, `EICAR_TEST_BYTES`, `ScannerError`.
- `queue.py` — `ScanQueue` Protocol, `ArqScanQueue`, `SCAN_TASK_NAME="scan_attachment"`, `scan_queue_from_pool`.
- `../../../worker/scan.py` — arq task `scan_attachment`: load by id → fetch from MinIO → ClamAV → `finalize_scan`. It scans drafts too. A transient error raises `arq.Retry` with a linear backoff, up to `scan_max_tries`. A row that disappears during the scan gives `"gone"`.
- `../../../worker/files_drafts.py` — hourly arq cron `purge_draft_attachments`: delete the expired drafts in batches (`FOR UPDATE SKIP LOCKED`), then remove their objects as best effort, then delete the expired draft tokens.

**Domain / data model:**
- One `attachment` row per upload.
- Columns: `id` (UUID PK), `application_id` (FK → `application.id`, `ondelete=CASCADE`, indexed, NULL for a draft only), `field_key` (nullable, links to a form field), `filename` (the display name, Unicode), `mime`, `size` (BigInt, CHECK `size <= 10485760`), `storage_key` (nullable, the MinIO object path `{application_id}/{uuid4hex}/{storage name}`, ASCII), `scanned` (bool, default false), `scan_result` (nullable: `NULL`/`clean`/virus-signature), `is_comparison_offer` (bool), `created_at` (tz-aware), `draft_token_hash` (bytea, HMAC of the draft token with `MAGIC_LINK_SECRET`) and `draft_expires_at` (tz-aware), both set on a draft only.
- A row has exactly one owner: an application, a ticket (`ticket_id`, be-tickets), a ticket note (`ticket_note_id`), a to-do comment (`todo_comment_id`, be-todos), an application comment (`comment_id`, be-applications), or a draft. `CHECK num_nonnulls(application_id, ticket_id, ticket_note_id, todo_comment_id, comment_id, draft_token_hash) = 1` and `CHECK (draft_token_hash IS NULL) = (draft_expires_at IS NULL)`. Every owner FK cascades and has an index. Two partial indexes (`WHERE draft_token_hash IS NOT NULL`) on `draft_expires_at` and `draft_token_hash`. Migrations `1ee8a0d3928c`, `86718c748401` (ticket owner), `269d13cd80a8` (the three message owners).
- **Chat files** (ticket note, to-do comment, application comment). The create schema of each thread extends `MessageFilesIn` (`attachmentIds` ≤ `MAX_MESSAGE_ATTACHMENTS` = 5, `draftToken`; an empty body needs a file, else 422 on `body`). The service calls `check_message_drafts` (ids without a token: 422 on `draftToken`), flushes the message and calls `bind_drafts(..., <owner>_id=...)` (exactly one owner, else `ValueError`). The read models carry `attachments: MessageAttachmentOut[]` (`id, filename, mime, size, scanState`: `scanning | clean | quarantined`), loaded per thread in one query by `message_attachments(owner, ids)`. Removing a message calls `delete_for_messages(owner, ids, actor)` (row, object best effort, `ATTACHMENT_DELETE` audit). A caller whose commit can still fail uses `drop_for_messages` (rows + audit, returns the storage keys) and calls `remove_objects(keys)` after its commit. `delete_for_ticket` also removes the note files, `delete_for_application` also the comment files. Every removal locks its rows `FOR UPDATE` in id order and deletes them all (flush) before the first `ATTACHMENT_DELETE` entry; a caller that writes an audit entry before the removal calls `lock_for_messages(owner, ids)` first (Gremium delete, application `delete_comment`, `lock_personal_todos` at the top of the principal erasure). Reason: the first audit write takes the chain advisory lock until the commit, and an infected `finalize_scan` locks its row first and then waits for that lock, so a row lock after the chain lock deadlocks.
- **Download dispatch.** The URL and download routes ask `owner_of(id)` first. An application file takes the old path. Every other owner goes through `_assert_owner_reader` and then `message_url` / `message_download_stream` (same `_ready` gates: 409, 410, 503). The read rule is the rule of the message: ticket and ticket note need `ticket.manage` (a deleted note: 404); a to-do comment needs a session, a live comment and `BoardAccess.can_read` on its board; an application comment needs `resolve_app_read`, `can_see_internal` for an internal one, and `assert_app_visible`. Every "no" is 404. `DELETE /api/attachments/{id}` stays application-only (404 for a message file).
- `attachment_draft_token` — `token_hash` (bytea PK, the same HMAC as `draft_token_hash`) and `expires_at` (tz-aware, indexed). The token lives here on its own: it stays valid until `expires_at`, also when its owner deletes the last draft. No FK links it to `attachment`. Same migration `1ee8a0d3928c`. The integration `engine` fixture truncates it.
- A draft object lives under `drafts/<attachment id>/<name>`. The bind keeps the key.
- Scan lifecycle: the row starts with `scanned=false`, which means quarantine. The worker then sets `scanned=true` and `scan_result='clean'`. On a hit it sets `scan_result=<signature>` and nulls `storage_key`. The object is deleted and gone for good.

**API surface:** (mounted under `/api`)
- `POST /api/applications/{application_id}/attachments` — multipart upload (≤10 MiB, streamed and capped) with the form fields `field_key` and `is_comparison_offer`. It needs app-edit rights and is rate-limited. Returns `AttachmentOut` with 201. Errors: 401/403/404/413/415/429/503.
- `GET /api/applications/{application_id}/attachments` — list the attachments (app-read).
- `GET /api/attachments/{attachment_id}` — returns `SignedUrlOut` that points at the `/download` route, not at a presigned bucket URL. It gives 409 while the scan runs, 410 for a quarantined or removed file, and 503 without storage.
- `GET /api/attachments/{attachment_id}/download` — streams the bytes server-side with `Content-Disposition: attachment`. The same gates apply. With `?inline=1` and a sniffed PDF or raster image (`_INLINE_MIMES`: PDF, PNG, JPEG, GIF, WebP) the response is `inline` for the preview dialog of the SPA, which frames it. Only that response may be framed, and only by the same origin: `PREVIEW_CSP` (`default-src 'none'; frame-ancestors 'self'; base-uri 'none'; form-action 'none'; sandbox`) and `X-Frame-Options: SAMEORIGIN`. Every other type (HTML, SVG, XML never reach the list) stays a forced download with the default `DENY` set. The nginx location of this route adds `DENY` only when the app sent no frame header (`map $ap_download_xfo`). The built-in PDF viewers of Firefox and Chromium render with `sandbox`.
- `POST /api/apply/attachments` — public draft upload of the wizard (Z4). Multipart with `file`, `field_key`, `is_comparison_offer` and `altcha`. The first upload has no `X-Draft-Token` header: an anonymous caller needs an ALTCHA solution (400 `altcha_failed` without), a logged-in principal does not. The response (`DraftAttachmentOut`, 201) carries `draftToken` and `draftExpiresAt`. A later upload sends the token in `X-Draft-Token` and needs no ALTCHA. Each upload moves the end of the token (`attachment_draft_token`, an upsert) and of ALL its drafts to now + `attachment_draft_ttl_days` (7). One token holds at most `attachment_draft_max_files` (20) files and `attachment_draft_max_bytes` (50 MB), else 413 `draft_quota_exceeded`. An unknown or expired token gives 422 `draft_token_invalid`; the wizard then starts a new draft. The route checks the token (`token_is_valid`, a primary-key read) BEFORE it reads and sniffs the file, so a random header costs no file work. A token without drafts is still valid. Size cap, body cap, rate limit (`rate_limit_attachments`) and MIME sniff as on the application upload. Errors: 400/413/415/422/429/503. The public `GET /api/site-config` names the three limits (`attachmentLimits`), so the wizard can show them below its drop zone.
- `DELETE /api/apply/attachments/{attachment_id}` — 204. Needs the owning token in `X-Draft-Token` (422 without the header). Another token, an unknown id or a bound attachment give 404. An expired draft can still be removed. The token stays valid after the delete. The delete is ONE Core `DELETE … WHERE id AND application_id IS NULL AND draft_token_hash … RETURNING storage_key`. Do not split it into a read and an ORM delete: a bind that commits between the two would let the delete remove a bound file. With one statement Postgres checks the conditions again after the bind lock, and the delete gives 404. The audit entry and the object removal come only after a deleted row.
- `POST /api/applications` with `attachmentIds` and `draftToken` binds the drafts (see `be-applications`).
- `DELETE /api/attachments/{attachment_id}` — 204. Open to a principal with `application.manage` or `application.edit_any`, to an applicant in edit scope, and to the logged-in creator. The applicant and the creator without `application.manage` get 409 when the current state has `edit_allowed = false` (`FilesService.assert_editable`). A delete is a data change, like a PATCH.

**Conventions & gotchas:**
- **A draft is invisible on every application path.** `get_attachment` answers 404 for a row without `application_id`, so the URL, download and delete routes never reach a draft, not even for an admin. Every application-scoped query filters `application_id IS NOT NULL` (`BOUND`): the list, `delete_for_application`, the guard `attachmentPresent` (`flow/context.py`), the anonymization, the audit labels (`resolve_target_labels`, `resolve_data_ids`), the privacy export and the discard of unconfirmed applications. A new query on `attachment` MUST do the same. `tests/integration/modules/files/test_drafts_hidden.py` is the regression test.
- **Bind on create (Z4).** `check_drafts` locks the listed drafts (`FOR UPDATE`) and needs each one owned by the token, not expired and not infected; a pending scan passes and stays quarantined. A failure gives 422 `draft_attachments_missing` with one error `attachmentIds.<id>` per failed id. With drafts, every reference in a `file` field must be one of `attachmentIds`. `bind_drafts` then sets `application_id` and clears both draft columns in the create transaction. A draft of the token that the submit does not list stays until the purge.
- **Comparison offers stay tagged attachments (O5, decided: no change).** An offer is an attachment with `is_comparison_offer = true`, optionally with a `field_key`. It has no reference to a cost position of a `positions` field, and none is planned.
- **Fail-closed quarantine** (`_ready_attachment`): an unscanned file (`scanned=false`) gives 409. An infected or removed file (`storage_key is None` or `_is_infected`) gives 410. NEVER loosen or invert the `if not attachment.scanned` check. It would serve unscanned content.
- **Download is server-side streamed, not presigned.** MinIO sits in the internal Docker network with no published port. An S3v4-presigned URL therefore binds the internal host, and the browser cannot reach it. `signed_url()` returns the app-relative URL `/api/attachments/{id}/download`. The bytes flow through nginx `/api/`. The `ObjectStorage` protocol carries **no** presigning method: it was removed once the last caller (`be-pdf`) was converted, so the mistake cannot be repeated by reaching for a method that exists.
- **No existence oracle:** an authenticated caller without read access to the application of the attachment gets 404, not 403. The auth check runs before the DB access on the URL, download and delete routes.
- **Access mirrors application read and edit** (not only the global `application.read`): `_resolve_attachment_read` calls `access.resolve_app_read`, so it covers `read_all`, view-applicant, committee-read and the logged-in creator. The attachments of an `isPII` field stay out of the list and answer 404 on the URL and download routes for a caller without the PII right (O21, `_pii_attachment_filter`). See `be-applications`.
- **Two names per upload.** `filename` is the display name of the client after `sanitize_display_name`: NFC, the last path component only, no control, lone-surrogate, line-separator, bidi override/isolate (U+202A–U+202E, U+2066–U+2069) or zero-width character (ZWJ/ZWNJ stay only between two visible characters, for emoji and scripts), no space or dot at an edge, at most 200 characters with the extension kept, else `upload`. So `Einführung €.pdf` stays `Einführung €.pdf`. The last segment of `storage_key` is `sanitize_storage_name` of that display name: `[A-Za-z0-9._- ]` only, accents folded (`Einfuhrung _.pdf`), never a separator or `..`. The application upload, the draft upload (and so every chat file), the invoice file (`be-budget`, which also cleans the `fileName` that `POST /invoices` sends back) and the CD logo (`be-admin`) follow this rule. Rows from before keep their `_` names. No migration: the columns are `text`.
- **Every download header goes through `content_disposition`.** Starlette encodes a header as Latin-1, so a `€` or an emoji in a plain `filename="…"` fails the response with 500. The helper cleans the name again (an old or client-sent name cannot bring CR, LF or a bidi control) and sends `filename="<ASCII fallback>"; filename*=UTF-8''<percent-encoded>` (RFC 6266, RFC 5987). The fallback holds no `"`, `\`, `%`, `;` or `/`. The attachment, invoice, CD logo, public protocol and backup downloads use it. A route with a fixed ASCII name may keep its literal header. The MCP tool `download_attachment` reads `filename*` first.
- **Content decides, not the extension:** `validate_upload` needs the sniffed MIME in the allowlist AND a matching `_EXT_TO_MIME` entry for the file extension. OOXML may sniff as `application/zip`, which is allowed only for `.docx/.xlsx/.pptx`. A mismatch or an empty result gives 415.
- **Upload is NOT edit-locked, delete IS:** a user may add an attachment in a locked state (submitted or approved, for example a late invoice). The form data stays PATCH-locked elsewhere. An applicant or creator DELETE in a locked state gives 409, so the receipts and comparison offers of a decided application stay. `application.manage` and `application.edit_any` keep the bypass. The applicant status page shows the delete control only with `canEdit()` (`[canDelete]` on `app-attachments-panel`).
- **Optional infrastructure degrades safely:** without MinIO an upload gives 503. Without a Redis/arq pool the file stays quarantined, because the scan is never enqueued. The API does not block. The module imports the heavy libraries (`magic`, `minio`, `clamd`) lazily, which keeps them out of the contract CI.
- **Enqueue is idempotent:** the job id `scan:<attachment_id>` coalesces duplicate enqueues.
- The upload, quarantine and delete actions write audit rows (`ATTACHMENT_UPLOAD` (F12), `ATTACHMENT_QUARANTINE`, `ATTACHMENT_DELETE`), see `be-audit`. The upload entry holds the field key, the comparison-offer flag, the MIME type and the size, never the file name. For a draft the entries carry `draft: true` instead of `application_id`. The purge writes no audit entry.
- **The scan tolerates a vanished row.** `finalize_scan` loads the row again (`populate_existing`) and catches `StaleDataError` on the quarantine audit write and on the commit, in one guard (`_commit_scan`). The audit write flushes the attachment UPDATE, so a vanished row can fail there first. It returns False and the task returns `"gone"`. On a finding it removes the object only after the commit. `delete_for_application` (GDPR anonymization) does NOT commit. The caller commits atomically.
- The edge nginx gives both upload routes (`/api/applications/{id}/attachments`, `/api/apply/attachments`) the 11m body limit. `enforce_attachment_body_cap` (Content-Length, `attachment_max_bytes` + 64 KiB) and the capped read stay as defense in depth.
- Tunables in settings: `attachment_max_bytes`, `attachment_url_ttl_seconds`, `attachment_draft_ttl_days`, `attachment_draft_max_files`, `attachment_draft_max_bytes`, `storage_enabled`/`minio_*`, `clamav_*`, `scan_max_tries`, `scan_retry_backoff_seconds`.
